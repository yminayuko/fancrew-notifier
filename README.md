# クラウドで監視する場合

**[CLOUD_SETUP.md](CLOUD_SETUP.md)** を参照してください。PCを起動し続ける必要はありません。以下はPCで実行する場合の説明です。

# ファンくる：東京都・一人のグルメモニター iPhone通知

PC（MacまたはLinux）で動かし、iPhoneへ通知するPythonプログラムです。iPhone単体で常時監視するものではありません。サイトの「グルメ」→「東京都の全掲載エリア」→「来店予定人数：一人」の検索結果を全ページ確認し、詳細ページで応募ボタンを確認した案件をiPhoneのntfyアプリへプッシュ通知します。通知に店名・条件・リンクを表示し、タップすると最初の案件を開けます。

「1人」は来店人数です。募集枠が1名かどうかではありません。1名～4名など、1人での来店が可能な案件も対象です。

## iPhoneの設定

1. App Storeで「ntfy」をインストールしてください。公式のiOSアプリ案内：https://docs.ntfy.sh/subscribe/phone/
2. ntfyを開き、通知を許可してください。
3. 下記のPC設定で表示するトピック名を、ntfyアプリの新しい購読（＋／Subscribe）に登録してください。サーバーは `https://ntfy.sh` です。

通知はntfy.shを経由します。店名・条件・案件URLが通知サービスへ送られます。ファンくるのログイン情報は送りません。トピック名はPCで128ビットの乱数を使って生成します。無料の公開トピック方式では、名前を知る人は通知の閲覧・投稿ができるため、`notification.json` とトピック名を他人に共有しないでください。

## PCの初回設定

Python 3.10以降と、使用するPlaywright版が対応するmacOSが必要です。現行版の公式動作環境はmacOS 14以降です。古いmacOSの場合はそのまま動作する保証がありません。

ZIPを展開し、ターミナルを開いて、`cd ` の後に展開した `fancrew_notifier` フォルダをドラッグしてEnterを押してください。そのフォルダで以下を順番に実行します。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
python fancrew_notifier.py --setup-iphone
```

表示されたトピック名（`fancrew-`で始まる文字列）を、iPhoneのntfyアプリに登録した後、PCで次を実行してください。既存の `notification.json` があれば `--setup-iphone` は同じトピックを表示します。

```bash
python fancrew_notifier.py --test-notification
```

iPhoneに「ファンくる通知テスト」が届くことを確認してください。PCの「送信を受け付けました」という表示だけでは、iPhoneへの到着を確認できません。届かない場合は、トピック名・サーバーが一致しているか、iPhoneの設定→通知→ntfyで許可されているか、集中モードで抑制されていないかを確認してください。

前のMac通知版を使っていた場合は停止してから、この版で設定・起動してください。元のフォルダにある `state.json` を引き継ぐと前回の監視状態を維持できます。

## 監視開始

```bash
source .venv/bin/activate
python fancrew_notifier.py
```

初回巡回は現在の状態を基準として保存します。2回目以降は、新しく見つかった募集中の案件と、実際に満員・終了を観測したあと応募ボタンが復活した案件を通知します。現在募集中の案件も初回から通知したい場合は次で開始します。

```bash
python fancrew_notifier.py --notify-existing
```

巡回終了後に30分待って、次の巡回を開始します。全件を順に確認するため、1巡回に数十分かかる場合があります。空きを観測した案件は巡回の最後にまとめて通知します。リアルタイム通知ではなく、短時間だけ空いた枠は検出できない場合があります。

巡回終了後、同じフォルダの `available.html` を開くと、応募ボタンを最後に確認できた案件の店名・条件・リンク・確認時刻を表示します。通知件数は新規／再開分、HTMLは募集中として最後に確認した一覧なので、件数は異なる場合があります。

通知はiPhoneで受け取ります。このChatGPTの会話を閉じても、PC上のプログラムが動いている間は監視します。**プログラムを起動するまでは通知されません。** ターミナルを閉じる、PCを終了する、スリープする、通信が切れると監視できません。iPhone側もインターネット接続が必要です。

Macのスリープを防ぎながら実行する場合：

```bash
caffeinate -i .venv/bin/python fancrew_notifier.py
```

停止はターミナルで `Control + C`。再開は同じコマンドです。再開時は保存した状態を引き継ぎます。Macでは `start.command` からも起動できます。実行権限エラーの場合は `chmod +x start.command` を実行してください。

## その他の使い方

```bash
# 1巡回だけ動かす
python fancrew_notifier.py --once
# 巡回終了後、15分待機する
python fancrew_notifier.py --interval 15
# 読み取りを行うブラウザ画面を表示
python fancrew_notifier.py --headed
# 判定テスト（サイトへ接続しません）
python -m unittest -v test_notifier.py
```

## 判定範囲と制約

- ログイン情報・パスワードは不要です。公開ページだけを確認します。会員限定の案件やアカウント固有の応募制限は監視対象外です。
- 表示されている応募ボタンが有効・可視で、満員／終了の表示がないときに「open」と判定します。実際の応募成功・当選を保証するものではありません。通知後にリンク先で最新の空き状況と、年齢・性別・来店日・参加履歴などの応募資格を確認してください。
- 自動応募は行いません。応募事前設問への回答やボタンのクリックも行いません。
- 判定不能・通信エラーを「満員」と扱わず、最後に確認した状態を保ちます。そのためHTMLには古い確認状態が残る場合があります。確認時刻を参照してください。
- 初回に読み取りできなかった案件が後から読めるようになった場合、新規として通知されることがあります。
- 監視間隔の間に満員→再開が完了すると、再開を検出できません。
- 通知サービスが送信を受け付けても、iPhoneの設定やネットワーク状況によって通知が遅れることがあります。配信成功を端末まで確認する機能はありません。
- 通知送信が失敗した巡回の状態は保存しません。次の巡回で再検出します。ただしその間に埋まった案件は通知できません。複数の通知に分割した途中で失敗した場合、一部は再送されることがあります。
- アクセス制限（403/429）や人間確認を検出したら停止します。通常の取得エラーは間隔を空けて再試行し、3巡回連続失敗で停止・通知します。
- サイトの画面変更で読み取りできなくなる可能性があります。その場合は `monitor.log` を確認してください。
- 個人用の低頻度な確認を想定しています。利用規約で運営妨害等が禁止されています。自動監視の許可を保証するものではないため、継続利用に際して必要に応じて運営元へ確認してください。

## 保存されるファイル

`notification.json`：iPhoneとPCで共有する通知トピック名（非公開で保管）。
`state.json`：前回の判定状態（削除すると初回扱い）。
`available.html`：応募ボタンを最後に確認した一覧。
`monitor.log`：巡回・通知・エラーの記録。
`monitor.lock`：二重起動を防ぐためのファイル。

これらはプログラムと同じフォルダに作成します。ログイン情報は保存しません。

## 確認済み事項（2026年10月6日）

実サイトの検索UIで東京都全掲載エリア・「一人」の条件を設定し、検索URL、案件カードの構造、ページ送り、詳細ページの応募ボタンを確認しました。募集状態の判定テストに加え、日本語を含む通知データ、リンク、分割、送信失敗の処理を模擬テストで検証しています。この作成環境では実際のiPhoneへの配信と全案件を対象とする長時間の実行は未検証です。利用するPCとiPhoneで通知テストと `--once` を実行してください。
